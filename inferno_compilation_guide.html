Comprehensive Technical Guide to Compile and Boot the Inferno Project

Here is an exhaustive technical guide for compiling and booting the Inferno project (ChefKissInc/Inferno) in a Userland environment on Android without root privileges.

1. PRoot Environment Setup in Termux

In a non-rooted environment, direct access to kernel device nodes (/dev/kvm) is blocked by SELinux and standard Android DACs. QEMU execution therefore relies exclusively on the TCG (Tiny Code Generator) dynamic translation engine.

A. Termux Initialization and Distribution Installation

Install proot-distro to deploy an Ubuntu 22.04 LTS (or 24.04) system, which provides recent versions of Clang, Meson, and Ninja.

# Update Termux repositories and install basic packages
pkg update -y && pkg upgrade -y
pkg install -y proot-distro git wget tar xz-utils

# Install and log into the Ubuntu environment
proot-distro install ubuntu
proot-distro login ubuntu --shared-tmp

B. Toolchain Installation in PRoot

Under the emulated Ubuntu rootfs, install the necessary dependencies to compile QEMU/Inferno:

apt update && apt upgrade -y
apt install -y     build-essential     clang     llvm     lld     ninja-build     meson     pkg-config     libglib2.0-dev     libpixman-1-dev     libfdt-dev     libcapstone-dev     libslirp-dev     libpng-dev     libjpeg-turbo8-dev     python3     python3-pip     python3-setuptools     python3-venv     bison     flex     libgcrypt20-dev     libgnutls28-dev     libepoxy-dev

# Apple image manipulation tools
apt install -y libssl-dev libcurl4-openssl-dev libxml2-dev libzip-dev

2. Cloning and Compiling Inferno

Inferno is a QEMU fork integrating the emulation of Apple Silicon SoCs (notably the t8030 / Apple A13 Bionic) and proprietary peripherals (AIC, Apple NVMe, Apple SEP, Apple SART, etc.).

A. Cloning the Repository

git clone --recursive https://github.com/ChefKissInc/Inferno.git
cd Inferno

B. Build Configuration (ARM64 TCG Optimizations)

The Google Tensor G3 SoC is based on the ARMv9-A architecture (1x Cortex-X3, 4x Cortex-A715, 4x Cortex-A510). Since we are targeting the aarch64 guest architecture on an aarch64 host, we configure the build to disable KVM, enable TCG, and apply host vector/scalar optimizations via Clang.

mkdir -p build && cd build

# CFLAGS optimized for the ARMv9 host (Tensor G3)
export CC=clang
export CXX=clang++
export CFLAGS="-O3 -mcpu=cortex-x3 -flto=thin -pipe"
export CXXFLAGS="-O3 -mcpu=cortex-x3 -flto=thin -pipe"
export LDFLAGS="-flto=thin -fuse-ld=lld"

../configure     --target-list=aarch64-softmmu     --enable-tcg     --disable-kvm     --disable-werror     --disable-docs     --disable-gtk     --disable-sdl     --enable-slirp     --enable-pie     --extra-cflags="$CFLAGS"     --extra-ldflags="$LDFLAGS"
Note: The GTK/SDL GUI can be enabled if you are using an X11 server (via Termux:X11), but to maximize TCG throughput, console/VNC display or -display none with a serial port is recommended.

C. Compilation

# Allocation limited to 4-6 threads to prevent the Android OOM-Killer from killing the compiler
ninja -j$(nproc) qemu-system-aarch64

3. Preparation of iOS 14.0 Beta 5 Images and Components

The iPhone 11 (iPhone12,1 / N104AP) running iOS 14.0 beta 5 (18A5351d) requires several elements extracted from the IPSW and multiple raw NVMe virtual disks.

A. IPSW Extraction (iPhone11,8,iPhone12,1_14.0_18A5351d_Restore.ipsw)

Decompress the IPSW archive (which is a zip file):

mkdir -p ~/ios_workspace/Restore && cd ~/ios_workspace
unzip -q /path/to/iPhone11,8,iPhone12,1_14.0_18A5351d_Restore.ipsw -d Restore/

Critical files required in Restore/:

  • Kernelcache: Restore/kernelcache.research.iphone12b
  • DeviceTree: Restore/Firmware/all_flash/DeviceTree.n104ap.im4p
  • TrustCache: Restore/Firmware/038-44135-124.dmg.trustcache
  • Ramdisk / Restorer: Restore/038-44135-124.dmg
  • SEP Firmware: Restore/Firmware/all_flash/sep-firmware.n104.RELEASE.im4p (or extracted version)

B. Generation of NVMe Partitions and Hardware State Files

The Apple NVMe controller emulated by Inferno requires dedicated namespaces (NSID 1 to 7) to match the A13 NAND topology:

cd ~/ios_workspace

# NSID 1: RootFS / Data (Minimum size of 8 GB for a test environment)
qemu-img create -f raw nvme.1 16G

# NSID 2: Firmware partition
qemu-img create -f raw nvme.2 128M

# NSID 3: SysCfg (System Configuration - Serial, Model, MAC, Calibration)
qemu-img create -f raw nvme.3 1M

# NSID 4: Control Bits / Factory data
qemu-img create -f raw nvme.4 1M

# NSID 5: Non-volatile NVRAM (managed by apple-nvram)
qemu-img create -f raw nvram 1M

# NSID 6: Effaceable storage (hardware erasure keys)
qemu-img create -f raw nvme.6 4M

# NSID 7/8: Panic Log
qemu-img create -f raw nvme.7 4M

# PFlash for the Secure Enclave Processor (SEP)
qemu-img create -f raw sep_nvram 1M
qemu-img create -f raw sep_ssc 1M

# Creation of a dummy root_ticket for AMFI validation bypass
touch root_ticket.der

4. Execution Command (qemu-system-aarch64)

Here is the command line to instantiate the t8030 machine (Apple A13 Bionic) with Darwin/XNU kernel arguments optimized for emulated execution:

~/Inferno/build/qemu-system-aarch64     -M t8030,trustcache=Restore/Firmware/038-44135-124.dmg.trustcache,ticket=root_ticket.der,kaslr-off=true     -kernel Restore/kernelcache.research.iphone12b     -dtb Restore/Firmware/all_flash/DeviceTree.n104ap.im4p     -initrd Restore/038-44135-124.dmg     -append "tlto_us=-1 mtxspin=-1 agm-genuine=1 agm-authentic=1 agm-trusted=1 serial=3 launchd_unsecure_cache=1 wdt=-1 -v -vm_compressor_wk_sw"     -smp 4     -m 4G     -serial mon:stdio     -nographic     -drive file=sep_nvram,if=pflash,format=raw     -drive file=sep_ssc,if=pflash,format=raw     -drive file=nvme.1,format=raw,if=none,id=drive.1     -device nvme-ns,drive=drive.1,bus=nvme-bus.0,nsid=1,nstype=1,logical_block_size=4096,physical_block_size=4096     -drive file=nvme.2,format=raw,if=none,id=drive.2     -device nvme-ns,drive=drive.2,bus=nvme-bus.0,nsid=2,nstype=2,logical_block_size=4096,physical_block_size=4096     -drive file=nvme.3,format=raw,if=none,id=drive.3     -device nvme-ns,drive=drive.3,bus=nvme-bus.0,nsid=3,nstype=3,logical_block_size=4096,physical_block_size=4096     -drive file=nvme.4,format=raw,if=none,id=drive.4     -device nvme-ns,drive=drive.4,bus=nvme-bus.0,nsid=4,nstype=4,logical_block_size=4096,physical_block_size=4096     -drive file=nvram,if=none,format=raw,id=nvram     -device apple-nvram,drive=nvram,bus=nvme-bus.0,nsid=5,nstype=5,id
